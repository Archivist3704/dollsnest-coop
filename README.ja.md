# Dolls Nest 協力mod

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語

『Dolls Nest』のための協力プレイ（PvE）modです。
mod 本体はネイティブ DLL と小さなローダー、そして仮想 LAN のときに優先して照合するリストでできています。

> **状態**：v685。2 台・3 台のマシンで実機確認済み（ゲーム 1.3.2）。このリポジトリはそのビルドのソースです。
>
> **ライセンス**：すべての権利を留保 —— **商用利用は許可していません**。末尾の「ライセンス」を参照。

**ダウンロード：[最新リリース](../../releases/latest)**

## プレイヤーの方へ

### インストール

1. [Releases](../../releases/latest) から `DollsNest-coop-v685.zip` をダウンロードし、Steam ライブラリのディレクトリに解凍します。

   ```
   <Steam ライブラリ>\steamapps\common\Dolls Nest\
   ```

   アーカイブには `DollsNest\Binaries\Win64\` の階層が入っているので、そこに解凍すれば
   `version.dll`、`dollsnest-coop.dll`、`peers.txt` が所定の位置に置かれます。

2. いつもどおり Steam からゲームを起動します。

3. ゲームのディレクトリに `dsh-proxy-load.txt` ができ、ゲーム中に **F7** でメニューが出れば成功です。

### 一緒に遊ぶ

1. 双方が Radmin VPN（または同種の仮想 LAN ツール）を入れ、同じネットワークに入ります。
2. `peers.txt` に全員の仮想 LAN アドレスを書きます（自分のアドレスも含む）。1 行に 1 つ。
3. ホストはマップに入り、**F7** を押して「ホストになる」を選びます。
4. クライアントは **F7** を押して「セッションに参加」を選びます。
5. 二人は同じマップにいる必要があります。別のマップでは接続できません。

### 制限

- 同じマップのときだけペアになれます。マップを移動するとセッションは終了します。
- 休憩地点での補給、または死亡でセッションは終了します。その後もう一度 **F7** でホスト／参加してください。
- ホストがセッションを終えてもクライアントには通知されません。自分でメニューから抜けてください。
- 2 人と 3 人で確認済み。4 人目は未検証です。
- ホストのボス撃破状態はクライアントのセーブに書き込まれます。進行度を合わせるためです。
- 進行度そのものは接続に影響しませんが、進みの遅い人をホストにするのがおすすめです。揃っていれば気にしなくて大丈夫です。
- ストーリーアイテムと進行度には保護が入っていますが、心配ならセーブをバックアップしてから遊んでください。

## 開発者の方へ

### ビルド

Visual Studio 2022/2026 のビルドツール（MSVC 19.5x）と CMake 3.2x 以上が必要です。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build\build.ps1 -BootstrapName dollsnest-coop-v685
```

出力は `out\bin\dollsnest-coop-v685.dll`（`.pdb` 付き）。成功すると `[build] OK` を表示して 0 で終了します。
0 以外で終わったときは、スクリプトが DLL を渡すのを拒否しています —— 成果物がない、要求した名前と違う、
DLL がソースより古い、のいずれかです。直前の `[build]` 警告に理由が出ます。

オフラインのテストスイートも同時にビルドされます。

```powershell
out\bin\dsh-selftest.exe
```

`checks: 734 failures: 0` と出れば通っています。

### 構成

| 場所 | 内容 |
|---|---|
| `Code/dsh-bootstrap` | mod がゲームに入る仕組み：ローダー、コマンド経路、F7 メニュー、ルーム探索 |
| `Code/dsh-game` | セッション本体：何を送り、何を作り、何を写すか |
| `Code/dsh-reflect` | ゲーム内 actor の読み書き。フィールド配置を知っている唯一の場所 |
| `Code/dsh-net` | UDP 転送、セッションのハンドシェイク、パケットの外枠 |
| `Code/dsh-sync` | 補間、再生クロック、送信のリズム |
| `Code/dsh-platform` | ログ、フックのラッパー、ファイルハッシュ |
| `Code/dsh-selftest` | オフラインのスイート。ゲームを必要としない部分 |
| `Code/dsh-proxy` | `version.dll` を装ってゲーム自身に mod を読み込ませる薄い殻 |
| `tools/build`、`tools/deploy` | ビルド、ゲームディレクトリへの配備、配布パッケージの作成 |

### おおまかな仕組み

ホストは自分の機体の位置と外見を毎秒 20 回サンプリングし、小さな UDP プロトコルで送ります。クライアントは
その外見を組み立て、自分の世界に同じ機体を作って同期させます。敵の体力、ミッション状態、弾、アイテムの
使用も同じ経路で運ばれます。世界の正解はホストが持ち、クライアントは起きたことを報告してホストが判断します。

### 補足

- `Code/third_party/minhook` は同梱の第三者ライブラリ（BSD-2-Clause）で、唯一の外部依存です。
- `Code/third_party/layout` は配布しません。オフセットはコードに埋め込み、実行時に検証します。
- 2 台のマシンは同じビルドでなければなりません。ログの最初の画面に出る `file sha256=` が一致している必要があります。
